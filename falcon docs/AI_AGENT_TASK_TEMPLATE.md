## Acceptance criteria
- [ ] Observable behavior 1
- [ ] Observable behavior 2
- [ ] Error/edge case behavior
- [ ] Tests added or updated
- [ ] Documentation updated where needed

## Constraints
- Preserve existing architecture and public contracts unless explicitly approved.
- Do not add dependencies without explaining why.
- Do not introduce AI into deterministic analysis.
- Do not execute repository scripts.
- Do not fabricate results.
- Keep changes minimal and focused.

## Required workflow
1. Summarize relevant existing code and propose a plan.
2. Identify assumptions and risks.
3. Implement the smallest complete change.
4. Add unit/integration/regression tests.
5. Run relevant tests, typecheck and lint.
6. Report changed files, commands/results and limitations.

## Final response format
- Summary
- Design decisions
- Files changed
- Tests executed and actual results
- Known limitations
- Suggested next task
